## How accesses behave

* **Transactions.** A request is accepted on the cycle `req_valid && req_ready`; that is the only moment side effects happen, so a stalled request or a response that is not taken never repeats an effect.
* **Byte enables.** A write updates only the enabled byte lanes; a read returns the enabled lanes and zero elsewhere. A 32-bit register occupies 4 lanes of its 16-byte word, a 64-bit register 8.
* **Reserved bits** read 0 and ignore writes.
* **Errors** (precedence order): ALP legality (`BAD_OPCODE`, `ALIGN_ERR`, `BAD_BE`, `BAD_ATTR`, `ACCESS_DENIED` for an invalid domain) > address outside every peripheral `DECODE_ERR` > region check (`ACCESS_DENIED` for permission, privilege or security, `BAD_ATTR` for a non-device memory type on a device region) > an enabled byte lane that belongs to no register `DECODE_ERR` > write to a register with no writable field or read of one with no readable field `ACCESS_DENIED` > a write refused by its hardware gate `TARGET_ERR`. An error response has zero data and **no register changes**, even on registers the same access also touched.
* **Hardware outputs are registered**: they change on the clock edge ending the accept cycle.
